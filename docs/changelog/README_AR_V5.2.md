## صفحة الموبايل (mobile.html)

أمثلة قبل ← بعد:

| قبل | بعد |
|---|---|
| رمز الموبايل (PIN) + فقرة «الرمز مكوّن من 6 أرقام، ويظهر في تبويب…» | الرمز (PIN) + «6 أرقام من تبويب الموبايل.» |
| بحث عن دواء | بحث |
| 📷 مسح الباركود / QR بالكاميرا | 📷 مسح الباركود |
| 🎥 اختبار الكاميرا فقط | 🎥 اختبار الكاميرا |
| تم رفض إذن الكاميرا أو تعذّر فتحها + فقرة طويلة عن القفل وchrome://flags | تعذّر فتح الكاميرا + «اسمح للكاميرا من أيقونة القفل 🔒 في كروم، ثم أعد المحاولة.» |
| سلة الفاتورة / السلة فارغة — أضف أدوية من البحث أعلاه. | السلة / السلة فارغة. |
| فواتيري — اليوم + فقرة عن الطباعة من الكمبيوتر | فواتيري + «الطباعة من الكمبيوتر.» |
| الباقي للعميل: … | الباقي: … |
| التشخيص: «البروتوكول: … | السياق الآمن: … | getUserMedia: … | إذن الكاميرا: …» | «بروتوكول: … | آمن: … | كاميرا: … | قارئ: … | ZXing: … | إذن: …» |
| رسائل الخطأ الطويلة («تعذر تحميل العملاء — تأكد أن الكمبيوتر والهاتف على نفس الواي فاي.») | رسائل قصيرة («تعذّر تحميل العملاء.») |

كل الأزرار والوظائف كما هي: نفس الـ IDs ونفس API ونفس PIN في الترويسة ونفس المسح (BarcodeDetector + ZXing) ونفس التحديث الحي. أهداف اللمس ≥44px كما هي، وRTL كما هو.

## تبويب الموبايل في الكمبيوتر (main.py: `build_mobile` + التشخيص)

- العنوان صار «📱 الموبايل والطباعة»، والأزرار «🛡️ إصلاح الاتصال»، «🖨️ طباعة»، «📋 كل الفواتير»، «🔑 تغيير الرمز»، «🌐 فتح على الكمبيوتر».
- التعليمات الطويلة (خطوات الهوت سبوت، خطوات الهاتف، شرح HTTPS وQR) صارت سطراً واحداً لكل منها.
- «اختبار الاتصال» يطبع سطوراً أقصر بنفس المعنى («✅ الفايروول: 8080 و 8443 مفتوحان (خاص + عام).»، «الخلاصة: الفايروول قافل 8443 — اضغط «إصلاح الاتصال» (كمسؤول).»). الكلمات المفتاحية التي يعتمد عليها منطق الخلاصة («للشبكات الخاصة فقط»، «لا توجد قاعدة للبورت») بقيت كما هي عمداً حتى لا ينكسر التشخيص.
