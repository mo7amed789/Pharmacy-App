# Pharmacy Enterprise v6.12 — تحديث تلقائي من GitHub

## الجديد
أي كود جديد يترفع على GitHub (فرع main) البرنامج يقدر يحدّث نفسه منه:

- **فحص تلقائي:** عند كل تشغيل، البرنامج يفحص GitHub في الخلفية بهدوء.
  لو فيه كود أحدث يظهر بانر «يوجد تحديث جديد» — ولو مفيش نت لا يزعجك
  بأي رسالة (الخطأ بيتسجل في الإعدادات بس).
- **من الإعدادات:** قسم «🔄 تحديثات البرنامج» فيه زر «التحقق الآن» وزر
  «تحميل وتثبيت التحديث» وسطر حالة يوضح الإصدار المثبّت وآخر فحص وآخر خطأ.
- **بعد التثبيت:** رسالة تطلب إعادة تشغيل البرنامج — الإصدار الجديد يعمل
  بعد إعادة التشغيل (وعنوان النافذة يوضح رقم الإصدار الجديد).

## بياناتك في أمان كامل
التحديث **لا يلمس أبداً**: قاعدة البيانات `pharmacy.db` وملفاتها،
`supabase_config.json` (مفتاح السحابة)، مجلدات `backups/` و`certs/`
و`receipts/`، وملفات `*.log` و`*.pem` و`invoice_counter.txt`. والمحدّث
لا يحذف أي ملف — يستبدل ويضيف فقط، وقبل الاستبدال يحفظ نسخة رجوع من كل
ملف قديم في `backups/code_update_<التاريخ>/` (يحتفظ بآخر 3 نسخ).

لو فشل أي ملف في منتصف التحديث (مثلاً ملف مقفل)، تُسترجع النسخة القديمة
كاملة تلقائياً وتظهر رسالة عربية توضح السبب — لا يوجد سيناريو «نصف
تحديث».

## طريقة الاستخدام
1. اعمل merge للـ PR واسحب الكود على جهازك (آخر مرة يدوياً).
2. أول تشغيل: البرنامج يسجّل الإصدار الحالي كأساس بصمت — لن يطلب تحديثاً.
3. من بعدها: أي push على main في GitHub، وعند تشغيل البرنامج (أو بالضغط
   على «التحقق الآن») يظهر التحديث، ودوس «تحميل وتثبيت» ثم أعد التشغيل.

## ملاحظات فنية
- الفحص يقرأ آخر commit من GitHub API (الريبو عام — لا يحتاج مفتاحاً)
  ويقارنه بآخر إصدار مثبّت محفوظ في قاعدة البيانات.
- التثبيت ينزّل أرشيف zip للـ commit من codeload.github.com ويفكّه في
  مجلد مؤقت ثم ينسخ ملفاً ملفاً؛ أرشيف لا يحتوي `main.py` يُرفض فوراً.
- التحديث يعمل على الكود فقط — ترقيات قاعدة البيانات (migrations) تعمل
  كالعادة عند أول تشغيل بعد التحديث لأنها جزء من الكود نفسه.
- مكتبة قياسية فقط (urllib + zipfile) — لا متطلبات جديدة.

## الملفات
- `updater.py` — فحص وتنزيل وتثبيت مع نسخ رجوع واسترجاع عند الفشل.
- `main.py` — قسم «تحديثات البرنامج» في الإعدادات + فحص عند التشغيل +
  رقم الإصدار في عنوان النافذة بقى v6.12.
- `tests/test_updater.py` — 9 اختبارات (8 بدون نت + 1 حي اختياري على
  GitHub الحقيقي عند RUN_LIVE_UPDATE_TEST=1).
