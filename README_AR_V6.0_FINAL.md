# Pharmacy Enterprise v6.0 — النسخة النهائية الكاملة

هذه النسخة تدمج كل التحديثات الأخيرة في ملف واحد كامل، وتبدأ فارغة (0 دواء، 0 فاتورة، 0 عميل، 0 مورد — مستخدمان فقط: admin و cashier).

## ما فيها (الثلاثة تحديثات معاً)

### v5.5 — تعديل الفواتير + سجل الفواتير على الموبايل (README_AR_V5.5.md)
- تعديل الفاتورة **قبل الطباعة** (من قائمة بانتظار الطباعة في تبويب الموبايل) **وبعدها** (من «كل الفواتير» أو تفاصيل الفاتورة): تغيير الكمية، حذف سطر، إضافة صنف جديد (باركود/اسم، علبة/شريط/حبة، FEFO)، تغيير الخصم والمدفوع وطريقة الدفع والعميل.
- عند الحفظ يظهر الإجمالي القديم والجديد و**الفرق** (يُحصَّل من العميل أو يُرد له). رقم الفاتورة وتاريخها لا يتغيران، والفاتورة المُرجعة لا تُعدَّل، وكل تعديل يُسجَّل في سجل التدقيق.
- المخزون يبقى صحيحاً: التعديل يعيد الأصناف القديمة ثم يخصم الجديدة في معاملة واحدة.
- **سجل الفواتير على الموبايل:** «📜 سجل الفواتير» يعرض كل الفواتير (كمبيوتر + موبايل) الأحدث أولاً، بحث برقم الفاتورة أو العميل أو التاريخ، وعرض الأصناف وتعديلها من الهاتف.

### v5.6 — إصلاح الكاميرا + كشف مصدر الطلبات الكثيرة (README_AR_V5.6.md)
- **الكاميرا:** السيرفر يولّد شهادة HTTPS تلقائياً عند التشغيل لتغطي IP الكمبيوتر الحالي (فإذا تغيّر IP لا تحتاج خطوة يدوية)، ولافتة حمراء برابط HTTPS مباشر عند فتح `http`، وزر «📸 صوّر الباركود» يعمل حتى على `http` وبدون إذن كاميرا.
- **الطلبات الكثيرة:** طلب واحد كل 8 ثوانٍ بدل طلبين كل 5 ثوانٍ، وتوقف كامل عند PIN خاطئ، وتراجع تدريجي عند الأخطاء، وتخزين مؤقت لـ ZXing (−69% طلبات)، وحد 120 طلباً/دقيقة لأي IP.
- **قسم «📋 الطلبات الأخيرة»** في تبويب الموبايل يعرض آخر الطلبات (الوقت + IP + المسار + النتيجة + المتصفح) مع ملخص حسب الجهاز، وملف `mobile_requests.log`.

### v5.7 — مراجعة منطق الأعمال الكاملة (README_AR_V5.7.md + ملف المراجعة)
- **الدواء منتهي الصلاحية لا يُباع أبداً** (كان FEFO يخصمه أولاً)، والتشغيلات بلا تاريخ تُباع آخراً.
- دين العميل الآجل يزيد بـ **(الإجمالي − المدفوع)** فقط، مع **تصحيح تلقائي لمرة واحدة** لأرصدة العملاء القدامى عند أول تشغيل بعد الترقية — **راجع أرصدة عملائك بعد التثبيت وقارنها بدفاترك**.
- حد الائتمان يُفرض في قاعدة البيانات (كمبيوتر + موبايل + تعديلات)، والبيع الآجل يرفض عميلاً غير موجود، والدفع الزائد مرفوض، والأسعار غير الصالحة (NaN) مرفوضة، والكميات الكسرية للحبوب مرفوضة.
- **إغلاق الوردية صار مطابقة حقيقية** (المتوقع من الوردية نفسها مقابل ما عدّدته، مع الفرق)، و**الربح يطرح الخصومات**، وأرقام الفواتير لا تتكرر بعد الاستعادة، وثغرة XSS في صفحة الهاتف أُغلقت.

## التثبيت

### (أ) تثبيت جديد (مجلد جديد — للبدء ببيانات حقيقية نظيفة)
1. فك ضغط `pharmacy-enterprise-v6.0-FINAL-full.zip` في مجلد جديد، مثلاً `C:\Users\mohamed\Desktop\pharmacy-enterprise-v6`.
2. شغّل `run.bat` **كمسؤول** (كليك يمين ← Run as administrator) أول مرة.
3. سجّل الدخول: `admin / admin123` (أو `cashier / cashier123`) — وغيّر كلمة المرور عند الطلب (8 أحرف على الأقل).
4. أدخل بياناتك بالترتيب: (1) اسم الصيدلية من الإعدادات، (2) الأدوية، (3) الموردون، (4) عملاء الآجل، (5) رصيد افتتاحي لكل دواء (تشغيلة + تاريخ صلاحية + كمية)، (6) بيع تجريبي + طباعة + نسخة احتياطية + اختبار الهاتف.

### (ب) ترقية المجلد الحالي (بياناتك تبقى)
1. **انسخ احتياطياً أولاً:** انسخ مجلد `C:\Users\mohamed\Desktop\pharmacy-enterprise` كاملاً في مكان آمن (أو من الإعدادات: «💾 نسخة احتياطية الآن»).
2. **انسخ ملفات الكود فقط** من هذا الملف فوق المجلد القديم واضغط Replace — الملفات هي: `main.py` و `database.py` و `mobile_server.py` و `mobile.html` و `ai_forecast.py` و `hotspot.py` و `firewall.py` و `qrgen.py` و `ui_theme.py` و `zxing.min.js` و `cert.pem` و `key.pem` و `run.bat` و `requirements.txt` و `drugs_template.csv` وملفات README و `DEFAULT_LOGINS.txt`.
3. **لا تحذف المجلد القديم ولا تستبدله** — قاعدة بياناتك `pharmacy.db` بداخله، وملفات النسخ الاحتياطي والسجلات تبقى.
4. شغّل `run.bat` كمسؤول، سجّل الدخول، و**راجع أرصدة العملاء الآجل** بعد التصحيح التلقائي.
